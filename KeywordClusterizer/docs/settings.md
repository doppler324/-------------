# Настройки `settings.json`

## `apiKey`

API-ключ DeepSeek для доступа к нейросети.

## `deepseek`

Настройки модели DeepSeek.

| Поле | По умолчанию | Описание |
|---|---|---|
| `model` | `deepseek-chat` | Базовая модель для шагов 1, 2, 4 (Draft / Mapping / Refinement) |
| `refactoringModel` | `deepseek-reasoner` | Модель для шага 3 (Refactoring). `deepseek-reasoner` даёт более глубокий аудит |
| `temperature` | `0.2` | Температура генерации: `0.0` = детерминированно, `1.0` = креативно |
| `maxTokens` | `100000` | Максимум токенов на ответ нейросети |
| `topP` | `1.0` | Top-p sampling (`1.0` = отключено) |

## `business`

Настройки бизнес-логики кластеризации.

| Поле | По умолчанию | Описание |
|---|---|---|
| `niche` | `сантехника` | Ниша сайта — подставляется в промпты для AI |
| `clusteringLogic` | `по интенту пользователя` | Логика группировки ключей |
| `granularityRule` | `кластеры от 2 до 10 ключей` | Правило гранулярности: формат `"от X до Y ключей"`. Парсится число `Y` как `maxClusterSize` |
| `chunkSize` | `100` | Размер чанка — сколько ключей отправлять AI за один запрос |

## `serp`

Настройки SERP-валидации через XmlRiver (Yandex XML).

| Поле | По умолчанию | Описание |
|---|---|---|
| `provider` | `xmlriver` | Провайдер поисковой выдачи |
| `xmlriverUser` | — | Логин XmlRiver (выдаётся при регистрации) |
| `xmlriverKey` | — | API-ключ XmlRiver |
| `enableValidation` | `false` | Включить SERP-валидацию кластеров |
| `minOverlap` | `0.4` | Минимальный Jaccard overlap (`0..1`) для признания интента совпадающим. Используется во всех фазах SERP-проверки |
| `topResultsCount` | `5` | Сколько URL из топа поисковой выдачи брать для каждого ключа |
| `sampleSize` | `3` | Сколько ключей из кластера опрашивать через XmlRiver для SERP-проверки |
| `maxRetries` | `3` | Сколько раз повторять запрос к XmlRiver при пустом ответе (транзиентные сбои) |
| `retryDelayMs` | `1000` | Задержка между повторами (в миллисекундах) |
| `maxConcurrency` | `3` | Максимум параллельных запросов к XmlRiver. XmlRiver позволяет до 10 потоков. При 10 потоках сбор SERP для 90 ключей занимает ~10-20 сек вместо 2-3 мин |
| `enabledForDraft` | `false` | Включить SERP-контекст для шага Draft. Перед первичной кластеризацией AI получит реальную выдачу Яндекса для первого чанка ключей (параллельно, все ключи чанка) |
| `enableFinalValidation` | `true` | Финальная проверка: после всей перегруппировки проверить overlap во всех кластерах |

## Пайплайн кластеризации

```
Шаг 1: Draft          → AI, первичная структура из первого чанка
Шаг 2: Mapping        → AI, распределение остальных ключей чанками
Шаг 3: Refactoring    → AI, аудит + merge дубликатов + split oversized
Шаг 4: Refinement     → AI, до 5 итераций (split + merge)
Шаг 4.5: Sem. Merge   → AI, дедупликация кластеров с одинаковым интентом
Шаг 4.6: SERP Valid.  → XmlRiver, 4 фазы:
  Фаза 1 — сбор SERP для всех сэмплированных ключей
  Фаза 2 — intra-cluster проверка (Jaccard overlap внутри каждого кластера)
  Фаза 3 — cross-cluster перегруппировка (bad-ключи → лучший кластер или "Неопределённые")
  Фаза 4 — финальная проверка overlap во всех кластерах
```
