Этап «Чистка ключевых слов» (режим 2)

Этап чистки ключевых запросов (Keyword Cleaner) — отдельный режим программы (пункт меню 2). Он предназначен для первичной подготовки семантического ядра: с помощью нейросети из списка ключей убирается «мусор» и оставляются только релевантные запросы, подходящие для дальнейшей кластеризации.

Что делает этап

  1. Читает ключевые слова из файла keywords.txt (по одному ключу на строку).
  2. Удаляет дубликаты (без учёта регистра).
  3. Разбивает список на пулы (по умолчанию до 1000 ключей в каждом).
  4. Каждый пул отправляется нейросети (многопоточно, по умолчанию 10 потоков).
  5. Нейросеть относит каждый ключ к одной из категорий: cleaned (релевантные), discarded (мусор), branded (брендовые).
  6. Ответ валидируется, результаты сохраняются в отдельные файлы.

Разделы справки

Запуск этапа

Подготовка файла keywords.txt, последовательность вопросов при запуске, ход выполнения.

Настройки

Секция cleaner в settings.json: модель, размер пула, выходные файлы, инструкции.

Типы запросов

Информационный и коммерческий отбор, правила исключения, обработка брендовых запросов.

Результаты

Выходные файлы (cleaned / discarded / branded / failed) и сводка в консоли.

Частые вопросы

Решение типичных ошибок: keywords.txt не найден, 401, failed.txt и др.

Выходные файлы

ФайлСодержимое
cleaned.txtРелевантные ключи — готовы к дальнейшей кластеризации
discarded.txtОтброшенные (мусорные) ключи
branded.txtБрендовые запросы (если выбран соответствующий режим)
failed.txtНеобработанные ключи (сбой пула + «потерянные» AI) — можно повторно запустить чистку с этим файлом

Дальнейший путь

Очищенный список из cleaned.txt используется как входной файл для этапа кластеризации (режим 1).

Подсказка: после чистки всегда проверяйте failed.txt — если он не пуст, запустите чистку повторно, указав его как входной файл, чтобы не потерять ключи.
